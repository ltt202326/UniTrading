# 跟单开发记录（尚不可交易）

此分支基于 PR #11。当前只有纯计算规划器和离线测试，未接入界面、账户事件或下单接口，也不能启动跟单。不得用于实盘。

## 范围

先验证单个 Tradovate 登录下的 Demo 子账户、一个明确到期合约和整数手数倍率。启动时所有参与账户须空仓无挂单；重启或断线后停止，不自动恢复。规划器只生成待审核的仓位调整，不发送订单；不支持保护单、挂单复制或跨登录，遇到上述情况阻止计算。

## 接入前的阻断项

- `AccountSnapshot` 没有账户持仓和订单是否完整的公开标记。Tradovate 在规格或均价缺失时省略部分持仓，且挂单映射会省略无法映射的订单和活动市价单；不能把空列表视为无持仓、无订单。须提供真实、同步一致的完整性信息及交易事件序列，再进行跟单。
- 现有 Tradovate 下单构造将 `isAutomated` 固定为 false。自动下单必须明确标记，并核对券商接口约束；所有订单必须经过现有账户风控。
- 规划输出不能直接循环重试或并发提交。每笔要持久化意图、使用唯一请求 ID、等待券商确认及持仓对账；部分成交、拒单、超时或未知结果必须停止并人工核对。恢复和应用生命周期也必须防止重复执行。
- 要处理跟随账户手动操作、停单期间主账户变化、行情过期、断线重连、账户变更及订单跨账户同步；保护单在完成绑定、撤单和竞态测试前不能声称支持。
- 手数限制、风险锁、状态和失败通知须作用于每个账户，且明确哪些账户未执行。应先使用模拟账户测试，再评估是否支持真实账户。
